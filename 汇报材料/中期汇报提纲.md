# 中期汇报提纲（建议 6 页，约 5 分钟）

1. **题目与问题（1 页）**：BIPIA 的课程规模部分复现。正常问答需要引用外部邮件/表格；攻击者把指令混进内容，观察模型是否把外部文本当成命令。
2. **论文与开源依据（1 页）**：给出 [论文](https://arxiv.org/abs/2312.14197)和[官方仓库](https://github.com/microsoft/BIPIA)。说明本地固定版本 `a004b69`，沿用官方数据、攻击文本、提示模板与显式提醒。
3. **实验设计（1 页）**：EmailQA、TableQA；两条攻击；开头/末尾注入；原始提示/显式提醒；同一上下文成对比较。每个任务试跑 4 条上下文、40 次 API 请求。
4. **已完成进度（1 页）**：官方仓库已获取；轻量 DeepSeek 适配器和测试已写；脚本可 dry-run、限制请求数、保存配置与响应。展示本机测试输出；此页不要把 dry-run 写成真实模型结果。
5. **风险与取舍（1 页）**：DeepSeek 不等于论文 GPT 模型；仅两种任务和两条攻击；完整短语判断低估改写后的成功；API 费用和调用限额需要控制。
6. **下一阶段（1 页）**：用自己的 API Key 跑小试，再按预算扩大到每个任务 20 条上下文；汇总成对 ASR、正常问答命中率与案例分析；最后填写结题结果表。

答辩时可用一句话界定贡献：“我优先复用了作者公开的实验资产，增加了适配 DeepSeek 的可重复小实验，并明确标注模型和指标的偏差。”
